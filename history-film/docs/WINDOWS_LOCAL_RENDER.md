# Локальный рендер на Windows — требования к проекту для Claude

**Статус:** это требования, а не готовый видеопроект. После получения Claude Code нужно создать реальный репозиторий, выполнить `git push` (если есть авторизация) и реализовать перечисленные команды.

## Принцип
- Весь видеорендер (черновик и финал) запускает пользователь **на своём Windows-компьютере**.
- В облаке Claude допускается подготовка кода, поиск/проверка ссылок, сохранение разрешённых изображений и простые кадры проверки. Не запускать облачный 2K/60FPS-рендер.
- Не использовать платные video-gen API и внешние сервисы рендера без отдельного согласия.
- Локальный предпросмотр: 720p30, только кадры 14–18. Финал: 2560×1440 60 FPS CFR, только после утверждения.

## Минимальные требования Windows
1. Git для Windows (и PowerShell или Windows Terminal).
2. Node.js актуальной LTS-ветки с npm.
3. FFmpeg + ffprobe в PATH (или явно документированная локальная установка).
4. Chromium для Playwright, если исходники получают скриншоты из браузера (например, `npx playwright install chromium`).
5. Достаточно места под оригиналы кадров, кэш и итоговые видео; не задавай неподтверждённую цифру.

## Пример команд, которые должны реально работать ПОСЛЕ выполнения проекта Claude

```powershell
git clone https://github.com/OWNER/REPO.git
cd REPO
npm ci
npm run doctor
npm run preview
npm run render:draft
```

Ожидаемый результат черновика: `output/draft_14-18.mp4`.

Для финала (когда будут все исходники, голос и одобрение):

```powershell
npm run render:final
```

Если авторизация GitHub нужна для приватного repo — `gh auth login` (GitHub CLI) или вход Git Credential Manager. **Никогда не проси передать токен в текст диалога.**

## Инструкция Claude по Github

1. Сделать полный рабочий исходный проект, проверить локальные команды насколько позволяет среда.
2. Репозиторий PRIVATE. Не включать секреты, чужие платные материалы, видео без права перепубликации или временные файлы.
3. Подготовить README с точной версией Node, FFmpeg, Playwright, работой с относительными путями и папкой выходов.
4. Если есть авторизованный GitHub CLI — `gh repo create <repo> --private --source . --remote origin --push`.
5. Если не авторизован, дать пошаговую команду для пользователя. Никаких выдуманных ссылок.
6. Убедиться, что git clone возвращает все нужные собственные исходники. Если часть assets не в Git, предоставить `asset_manifest.json` и работающий локальный способ получения, с учётом лицензий.
7. Условие успеха: пользователь может на своём компьютере запустить черновик **без возвращения в Claude за дополнительным кодом**.
