# START HERE — TrueDad: монтаж с КАДРА 14 по КАДР 78

Ты — Claude Code, технический режиссёр монтажа TrueDad. **Это проект для локального рендера на Windows-компьютере владельца.** Нельзя выполнять дорогой рендер в облаке, заказывать платную генерацию видео, расходовать API/кредиты или массово генерировать CGI без явного разрешения.

## РЕЖИССЁРСКАЯ ЦЕЛЬ

Снять визуальную усталость от презентаций: **больше настоящего плавного футажа; меньше графики, вспышек и сложной анимации**. Смотреть на тему как на спокойную документалистику Steam/CS:GO, а не как на рекламный трейлер.

- Преимущество: реальные исторические видеозаписи/архивные интерфейсы, захваты официальных новостей и прокрутка страниц, реальные предметы и старые коллекции; статичное фото слегка оживлять только когда нет возможности показать видео.
- Типичная длительность одного осмысленного плана ~4–8 секунд, иногда больше по фразе. Не резать по таймеру, не использовать forced cut каждые 1–2 секунды.
- Плавная камера, правильная композиция, естественная прокрутка/курсор. Меньше текстовых плашек. Графика уместна только для объяснения экономики или изменений механики (спред, 7 дней, 5 Covert, архивные цифры).
- Без сложных 3D-сцен, сотен частиц, постоянных сеток, fake UI, типовых шаблонов презентаций, искусственно нарисованных «новостей».
- Каждая архивная новость: в источниках есть URL; сними экран **настоящей страницы** в браузере Playwright, при необходимости запиши плавную прокрутку или сделай 2–3 скриншота для управляемого панорамирования. Не выдавай реконструкцию за исходный скрин.

## РАМКИ / МАТЕРИАЛЫ

1. Работать **только с кадрами 14–78** из `SCENES.json`. Оригинальная нумерация сохранена. Не делать заново кадры 1–13 и вступление.
2. Полный `СЦЕНАРИЙ_полный_для_контекста.docx` прилагается только для понимания истории и будущей озвучки. Не используй его как повод монтировать кадры 1–13.
3. В `SOURCES.json` только источники нужных сцен. Статус «OK» означает результаты **предыдущей** проверки, не гарантию: проверь URL браузером и веди `link_audit.csv` (OK / blocked / irrelevant / replaced, HTTP и что фактически видно).
4. Локальные архивы в `assets/local`. Не переименовывай оригиналы; зафиксируй источник. Финансовые значения из курса — **архивные опорные точки**, не ежедневные цены. Не фабрикуй продажи.
5. `1117.MP3` сознательно не приложен: это озвучка вступления, а не сцен 14–78. Настоящая озвучка нового участка ещё отсутствует. Работай с временным `VOICE_PENDING`-таймингом, не имитируй авторский голос.
6. Не совершай реальные игровые сделки и не используй чужой контент без оценки прав; для GitHub по умолчанию создавай **приватный** репозиторий, особенно поскольку есть архивные материалы курса. Не включай токены в репозиторий.

## ЖЁСТКИЙ ПОРЯДОК / БЮДЖЕТ КРЕДИТОВ

**ЭТАП 1.** Оценить 65 сцен, источники, требуемые медиа, возможности Windows/Node/FFmpeg. Создать текстовый shot-plan и бюджетный asset-plan. Сразу не скачивать всё подряд.

**ЭТАП 2 — первый черновик ТОЛЬКО кадров 14–18.** Примерно 40–70 секунд, с временными длительностями и маркировкой `VOICE_PENDING`; в основе уже доступные 2013/2014 редкие скины, Winter Sale, старые подарки и пример 500/1500/2000 ₽. Можно короче/длиннее, если этого требует содержание; не пытайся угадать финальную длину без аудио.

Для первого черновика: **локальный preview 1280×720, 30 FPS**, доступен просмотр в браузере/Remotion Studio; локальная команда `npm run render:draft` создаёт MP4 на ПК владельца. Никаких облачных рендеров, платных генераций видео и массовых анимаций. Используй 5–8 плавных осмысленных планов, а не 20 коротких.

**ЭТАП 3 — остановиться и запросить обратную связь.** После отправки проекта и команд владельцу **не переходить к кадру 19, не скачивать сотни медиа и не запускать 2K/60 FPS**, пока не получено одобрение чернового стиля. Оставить `FEEDBACK.md` с вопросами о темпе, подборе материалов и читаемости.

**ЭТАП 4.** Только после явного одобрения — монтировать главы небольшими батчами, согласуя результаты. Повторно использовать графические/технические компоненты. Сначала настоящий футаж, потом необходимая графика, и лишь в крайнем случае дорогие эффекты.

**ЭТАП 5.** Только после получения новых озвучек и утверждения всего монтажа — финальный 2560×1440 60 CFR FPS рендер **на ПК владельца**. Не обещай полноценный финальный фильм без голоса.

## ОБЯЗАТЕЛЬНЫЙ ТЕХНИЧЕСКИЙ ВЫХОД: РАБОЧИЙ GITHUB ПРОЕКТ

Ты должен **написать запускаемый проект**, разместить его на GitHub и предоставить рабочий URL репозитория для `git clone`. Обычное описание, кадры-превью или DOCX вместо проекта неприемлемы.

**Используй Remotion + Node.js (LTS) + Playwright для записей страниц + FFmpeg для аудио/проверок**, если эти инструменты доступны; допускается альтернативный воспроизводимый стек, но без проприетарных облачных сервисов. Все пути должны быть относительными — не использовать `/mnt/data`/папки Claude в исходниках. Windows PowerShell — основной целевой терминал.

Реализуй в `package.json` как минимум работающие команды:
- `npm run doctor` — проверка Node/FFmpeg/браузера/файлов, понятные сообщения об отсутствующих зависимостях.
- `npm run preview` — открыть локальный просмотр/Studio без платной внешней генерации.
- `npm run render:draft` — смонтировать **только кадры 14–18** в 720p30 локально, сохранить `output/draft_14-18.mp4`.
- `npm run render:final` — локальный 2560×1440/60FPS, доступен только когда материалы для утверждённой части готовы; не исполнять автоматически.
- `npm run audit:links` — создать или обновить `link_audit.csv`, не скачивая массово медиа.

Обязательные файлы: `package.json`, `package-lock.json`, `README.md`, `src/`, `scripts/`, `assets/`, `SCENES.json`, `SOURCES.json`, `.gitignore`, `LICENSES_AND_SOURCES.md`, `FEEDBACK.md` и по желанию `shot_timeline.json`.

GitHub: **приватный репозиторий по умолчанию**. Перед созданием публичного обязательно спроси согласие владельца. Если авторизация на GitHub не выполнена, не делай вид, что загрузил проект: покажи, как пройти `gh auth login`, подготовь `git init`, `git add`, `git commit` и `gh repo create ... --private --source . --remote origin --push`, предоставь последнюю команду для ручного исполнения. Если есть права и пользователь разрешил публикацию в приватном репозитории, реально создай и push; верни фактический URL и проверь, что репозиторий доступен владельцу. Не клади пароли/ключи/токены ни в файл, ни в git историю.

Для личных архивов курса GitHub должен оставаться приватным. Если исходники содержат чужие видеозаписи, загружай в GitHub только лицензируемые/разрешённые файлы либо манифест ссылок и локальный сценарий получения через браузер; не публикуй защищённые материалы без права распространения. Если отдельный файл >100 МБ, не пытайся впихнуть его в обычный Git: используй Git LFS или отдельный локальный assets-import по документации.

## ПЕРВОПРИЧИНЫ КОНТРОЛЯ КАЧЕСТВА

- Видео должно быть не презентацией, а спокойным документальным фильмом. Разборчивые источники и натуральное движение важнее «вау-эффектов».
- Стоимость: никакой платной AI video generation, никаких облачных GPU, никаких многократных дорогих рендеров без разрешения.
- Изображения и видео: проверять дату, содержание, права и разрешение; добавлять замены при блокировке. Скриншоты новостей — только настоящие.
- План/проект должны быть понятны владельцу без навыков программиста. Локальный запуск одной командой для черновика.
- Для черновика отдельный low-res MP4, а не 2K/60 FPS на каждом изменении.
- Не представлять черновик 14–18 как готовый ролик всего фильма. Не делать следующие сцены до ответа владельца.
